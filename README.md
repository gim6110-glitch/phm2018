# D-A-A LOOP 식각 장비 AI 관제탑

특성화고 10차시 수업에서 실제 식각 장비의 과거 기록을 읽고, AI 점수와 판단 기준을 비교하며, 안전 정지와 복구 절차를 연습하는 교육용 웹사이트입니다. 사용자 계정이나 API 키를 요구하는 기능은 없습니다. GitHub에 파일을 올리고 Netlify로 배포하면 웹주소로 접속해 사용합니다.

## 1. GitHub에 올릴 것

이 ZIP을 먼저 풉니다. 압축을 푼 폴더의 **내용물**을 저장소 최상위에 올립니다.

| 최상위 항목 | 역할 |
|---|---|
| `index.html` | 첫 화면 |
| `assets/` | 화면 디자인, JavaScript, 그림, 실습 결과 |
| `netlify.toml` | 게시 폴더와 응답 설정 |
| `README.md` | 이 안내 |
| `THIRD_PARTY_NOTICES.txt` | 포함된 CSV 도구의 저작권 고지 |
| `DATA_SOURCES.md` | 데이터의 출처와 해석 범위 |

GitHub 웹에서 저장소를 연 뒤 **Add file → Upload files**를 선택하고, 위 파일과 assets 폴더를 함께 끌어 넣어 Commit changes로 저장합니다. 저장소 첫 화면에서 index.html이 보여야 합니다. ZIP 한 개만 올리거나, assets 폴더를 빠뜨리면 작동하지 않습니다. 기존 저장소를 쓰는 경우 같은 경로의 기존 파일을 확인한 뒤 이번 자료로 교체합니다.

## 2. Netlify 설정

Netlify에서 Git 저장소를 연결하는 가져오기 기능을 선택하고 해당 GitHub 저장소와 배포 브랜치를 지정합니다. 이 자료는 이미 실행 가능한 정적 파일입니다.

| 항목 | 설정 |
|---|---|
| Framework | 자동 감지되지 않아도 정상 |
| Base directory | 비워 둠 |
| Build command | 비워 둠 |
| Publish directory | `.` |
| Environment variables | 필요 없음 |

동봉한 netlify.toml에도 게시 폴더 `.`가 지정되어 있습니다. 최초 배포를 시작한 뒤 Netlify가 발급한 사이트 URL을 엽니다. GitHub 파일 주소나 Netlify 관리 화면 주소 대신 **실제 사이트 URL**을 학생에게 안내합니다. 공개 접속 설정과 학교망 접속 가능 여부는 로그아웃한 다른 기기에서도 확인합니다. GitHub와 Netlify의 게시 작업은 교사가 진행합니다.

공식 설정 안내: https://docs.netlify.com/build/configure-builds/overview/

## 3. 바로 확인하는 수업 경로

### 5차시
1. 데이터 준비에서 **가상 점수 연습**을 선택합니다.
2. 기준 A/B 비교에서 **기준 A 선택**: 일반 관찰 6, 재검토 3, 점검 요청 3건.
3. **기준 B 선택**: 8, 2, 2건. 같은 점수표에서 기준만 바꿉니다.
4. 활동지 3에 수치, 선택 이유, 더 확인할 정보를 씁니다.
5. 실제 자료로 확장할 때는 **실제 자료 불러오기**를 누릅니다. A는 1313·8·0건, B는 1321·0·0건입니다. 가상 12개와 실제 1321행을 구별합니다.

### 6~7차시
실제 자료에서 기준 A를 선택하고 사례 상세보기에서 재검토 사례 한 건을 고릅니다. 공정조건과 센서 추세를 살펴보고 추가 확인을 기록합니다. 센서 그래프의 띠는 검증자료의 분포이며 정상 한계값이 아닙니다.

### 9차시
1. 위쪽 **9차시 안전 시험 시작**을 누르면 가상 점수 연습으로 전환됩니다. 묶음 A를 선택합니다.
2. READY에서 START를 눌러 RUN을 확인합니다.
3. SAFETY_OK를 0으로 바꾸면 STOP과 운전허가 차단이 표시됩니다.
4. SAFETY_OK를 1로 복구해도 STOP이 유지됩니다. ACK는 부저만 끕니다.
5. RESET의 네 단계에서 안전조건, 원인 메모, 복구 확인을 진행합니다.
6. 현재 점수·통신·점검 조건이 모두 충족되면 READY입니다. 별도의 START를 눌러야 운전합니다.
7. ACTION·통신 이상·무효 신호가 남아 있으면 CHECK와 시작 차단이 유지됩니다.

기준 후보 A/B와 관제 시험 묶음 A/B/C는 다른 구분입니다. 실제 자료에는 현재 기준의 C 사례가 없어 실제 C 파일을 만들지 않았습니다. 가상 A/B/C는 절차 연습용으로 명시되어 있습니다.

### 10차시
활동 로그에서 **로그 CSV 저장**을 누릅니다. 기준선 또는 확인 질문 하나만 고치고 같은 조건에서 다시 확인합니다. 가상 A에서 T1만 0.60으로 바꾸고 T2=0.65를 유지하면 8·1·3건입니다.

## 4. 내 Colab 결과 넣기

데이터 준비의 **파일 선택**에서 score_validation.csv, score_test.csv, model_summary.json 세 개를 함께 선택합니다. 필요하면 bundle_A_normal.csv와 bundle_B_review.csv도 넣습니다. 원본 train_normal.csv를 점수 결과 대신 넣지 않습니다. 파일 하나는 10MB 이내이며, CSV에는 time 또는 timestamp, row_id, data_role, anomaly_score 열이 필요합니다. 비어 있거나 숫자가 아닌 이상점수는 거부합니다.

Test 건수는 기준을 최종 확정한 뒤 표시됩니다. 결과를 보고 다시 조정하면 독립적인 마지막 확인으로 해석할 수 없습니다. 현재 제공 자료는 시간·운전조건 혼합의 한계가 있어 미래 고장 예측 성능을 입증하지 않습니다.

## 5. 기록과 운영

- 입력 파일은 현재 브라우저에서 처리합니다. 별도 업로드 서버가 없습니다.
- 활동 로그와 기준 선택은 현재 브라우저에 저장됩니다. 기기 사이에 자동 공유되지 않으므로 수업 후 CSV와 제출 JSON을 내려받습니다.
- 개인 이름 대신 모둠 코드나 가명 번호를 사용하면 수업 기록을 구분하기 쉽습니다.
- 외부 CDN이나 AI 서비스 호출 없이 동봉된 JavaScript·CSS·데이터로 동작합니다. 웹사이트에 처음 접속하려면 배포 서버에 연결되어야 합니다.
- 이 자료는 실제 설비와 연결하지 않는 교육용 모의 운전입니다.

## 6. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 첫 화면이 404 | 저장소 최상위의 index.html, 게시 폴더 `.` |
| 글·버튼 모양이 깨짐 | assets 폴더 전체 업로드 여부, 파일 대소문자 |
| 실제 자료 불러오기 실패 | assets/data의 다섯 파일 존재 여부, 배포 완료 여부 |
| START가 비활성 | STOP·CHECK·통신 이상·현재 ACTION 여부. 원인을 확인하고 복구 절차 진행 |
| 새 묶음을 선택할 수 없음 | 운전 중이거나 STOP·CHECK이면 기존 절차를 먼저 마침 |
| 다른 PC에 로그가 없음 | 로그는 기기별 저장. CSV로 내려받아 제출 |
| 최신 파일이 안 보임 | GitHub 변경 저장 및 Netlify 배포 완료 확인 후 새로고침 |

## 7. 확인한 범위

2026-10-21 로컬 HTTP 환경의 Chromium에서 A/B 건수, 실제 파일 업로드와 동봉 데이터 불러오기, STOP 유지, ACK, RESET 후 READY, 별도 START, ACTION 잔존 차단, 통신 이상, 무효 AI 신호, 로그 CSV 다운로드·재접속 유지와 모바일 폭 390px을 확인했습니다. 실제 Netlify 사이트의 배포·학교망·학생 기기는 교사가 게시 후 확인합니다.
